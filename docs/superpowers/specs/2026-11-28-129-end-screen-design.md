# #129 ゲームの終わりの見出しを結果で決め、まちがいの粒をやめる（設計）

- ステータス: in-progress（PO 承認 2026-11-28）
- 対象: 1.0.5

## 意図
- 子どもが、がんばった回を「ほめられて終わる」。4/5 正解でも最後をまちがえると「残念...」と 💔 で終わる今の作りをやめる
- 親から見て、終わりの画面の見出しと星の数が食い違わない

## 今の動き（2026-11-28 の main、コードを読んだ結果）
- `FeedbackView`（`Views/Game/Components/Feedback/FeedbackView.swift:11`）は `lastAnswerCorrect` だけで「正解！よくできました！」／「残念... 次は頑張ろう！」を分ける。途中の正解とゲームの終わりで同じ部品を使う
- 途中でまちがえたときは #82 の「正解を見せる」画面になり `FeedbackView` は出ない。「残念...」が出るのは最後の 1 問をまちがえて終わったときだけ
- 粒（`GameView.swift:119`、`ParticleEffectView`）は `showFeedback` の間ずっと出て、まちがいなら ❌💔😢。ゲームが終わっても `showFeedback` は true のまま

## 目標
- ゲームが終わったときの見出しを星の数（`earnedStars`）で決める（PO 判断）
  - ★3「すごい！ ぜんぶ せいかい！」
  - ★1〜2「よく できたね！」
  - ★0「さいごまで がんばったね！」
- 見出しはひらがな（PO 判断）
- まちがえたときの粒を出さない（PO 判断）

## やらないこと（非目標）
- 見出しの読み上げ（最後の問題の単語の読み上げと重なるかを確かめていないため。次の段）
- 途中で正解したときの「正解！よくできました！」、結果の欄（`GameResultView` の「ゲーム終了！」「スコア」「正解率」）の文言。#74 の全体の見直しで扱う
- 星の計算（`GameLogicService.calculateStars`）は変えない

## 失敗とみなすもの（反目標）
- 星の数と見出しの段階が食い違う（例: ★3 なのに「よく できたね！」）
- 途中で正解したときの表示が変わる

## 作り方
| 案 | 中身 | 判断 |
|---|---|---|
| A | 見出しを決める関数（星の数 → 見出し）と、粒を出す条件の関数を作り、ユニットテストで守る。`FeedbackView` はゲームが終わったときだけ見出しの関数を使う | **採用**（PO 承認） |
| B | 終わりの画面専用の View を新しく作る | 結果の欄の部品と重複し、目的に対して大きい |
| C | `FeedbackView` の中に分岐を直接書く | 文言と段階をテストで守れない |

## Claude の判断（PO が設計の承認で了承）
- ゲームが終わったら、回答ごとの粒は止める。お祝いは既存の紙吹雪（★1 以上、`GameView.swift:126`）に任せる
- 時間切れで終わったときも星の数で見出しを決める
- 終わりの画面のアイコンは星のマーク 1 つにそろえ、赤い ✖ は出さない

## 物差し
- 見出しと星の段階（0・1・2・3）の対応、粒を出す条件（正誤 × 終了 × 視差効果）を、ユニットテストで全通り確かめる
- 見た目は、シミュレータで ★0・★2・★3 の終わりの画面を撮って PR に貼る（一時的な XCUITest か UserDefaults の仕込み。方法は計画で決める）
